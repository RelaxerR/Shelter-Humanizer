# Приёмка macOS — 18 октября 2026

Среда: macOS 27.0 (26A428), Apple Silicon arm64, 10 логических CPU.
Homebrew Python 3.14.8_2 / Python 3.14.8, Tcl/Tk 9.1.0,
PyInstaller 6.22.3, Ruff 0.16.9. Исходное дерево было чистым, main форка — 008ae35.
Разработка ведётся в `fix/macos-desktop`, upstream не изменяется.

## Проверено

- 220 unittest-проверок: успешно, 6 Windows-проверок пропущены на Mac.
  Ruff lint/format и `git diff --check` проходят. Новые тесты проверяют Command/Option/
  Control, русские keysyms, малые дельты Aqua, пути и фильтрацию настроек, внешнюю
  Ollama без запуска managed runtime, события контекстного меню и нативного Edit menu.
- Создание настоящего Tk-окна и диалогов, обе темы, размеры диалогов при разных
  масштабах, отсутствие Listbox у нативного Aqua Combobox, логотип.
- Офлайн-анализ и очистка, UTF-8 TXT import/export, JSON export, русский текст и emoji.
  Frozen self-test вызывает настоящие обработчики GUI; только выбор пути в файловом
  диалоге подставляется автоматически. Временные пути содержат пробелы и кириллицу.
- Длинный многострочный буфер: 1800 повторов русской строки с 👩‍💻, без потери символов.
  Используются системные `pbcopy`/`pbpaste`, а не повреждающая длинный UTF-8 ветка Tk.
- Через системные клавиатурные события в исходном GUI проверены ⌘A/C/V/X/Z и ⇧⌘Z;
  наблюдались удаление, восстановление и повтор удаления текста. Раскладки Russian
  и U.S. переключались штатным Control-Space; алиасы обеих раскладок покрыты тестом.
- `.app` открыта из Finder двойным кликом. В ней есть Python framework, Tcl/Tk,
  `_tkinter`, ресурсы и ICNS, версия bundle 1.1.1, Retina metadata.
  Минимальная версия macOS у конкретной сборки равна версии хоста сборки: более
  старые версии не объявляются проверенными. Intel Mac не заявлен.
- ZIP сохраняет executable bits и framework symlinks через `ditto`; SHA256 рядом.
  Сборщик проверяет Mach-O зависимости: допустимы bundle-relative и системные пути,
  ссылки на Homebrew/Python сборочной машины запрещены. Лицензии Python, Tcl/Tk,
  PyInstaller и собранных Homebrew-библиотек включаются в архив и внутрь `.app`.

## Настоящая Ollama

До работы Ollama и моделей не было. С разрешения владельца установлена Homebrew
Ollama 0.40.6; отдельно запущена `ollama serve` на 127.0.0.1:11434, без автозапуска
при входе. Загружена только разрешённая `qwen3:0.6b` (~522 МБ, основной blob 7f4030143c1c).
Сервис и модель не входят в дистрибутив Shelter.

Проверены `/api/tags`, выбор установленной модели, реальная потоковая генерация
через `App.run`, отмена GUI-задания с сохранением предыдущего результата, прерывание
HTTP-запроса во время генерации, сохранение выбора и повторное создание GUI.
После `App.close()` внешний сервер отвечает и модель остаётся доступна.
Проверка выполнена из исходников и из frozen executable с `PATH=/usr/bin:/bin`.

Воспроизведение (модель должна быть установлена заранее; команда ничего не скачивает):

```sh
.venv/bin/python launcher.py --ollama-self-test qwen3:0.6b /tmp/source-ollama.json
"dist/darwin/Shelter-Humanizer.app/Contents/MacOS/Shelter-Humanizer" \
  --ollama-self-test qwen3:0.6b /tmp/frozen-ollama.json
```

Оба успешных receipt содержат `gui_generation`, `transport_cancelled`,
`selection_restored`, `previous_result_preserved`, `external_service_survived_close`.
Тест использует собственные временные настройки, пользовательский файл не меняется.
Ошибки соединения, пустой список моделей, отмена и HTTP/NDJSON ошибки дополнительно
проверяются существующими тестами локального HTTP-сервера.

**Качество 0.6b не прошло редакторскую приёмку.** Первый пример был отклонён защитой
данных за изменённые/добавленные защищённые фрагменты. На коротком примере модель
добавляла пояснение или сокращала текст. Повторный ручной запуск frozen acceptance
прошёл; в приложении нет автоматических повторов или ослабления защиты ради теста.
Модель годится для проверки подключения, не рекомендуется как качественный редактор.
Более крупные модели не загружались и не проверялись.

## Оставшиеся ограничения

- Физические правый клик, Control-click и жесты трекпада требуют ручного подтверждения
  владельцем Mac. Инструмент компьютерного управления передавал все координатные
  клики в одну неверную точку (это подтверждено отдельным Tk probe). Кодовые привязки
  и прокрутка по малым дельтам протестированы; это не заменяет аппаратную приёмку.
  До подтверждения issue #3 остаётся открытым и не получает `Closes`.
- Нативные TXT-диалоги созданы Tk, но выбор реального файла через Finder/file picker
  не автоматизирован: перечисленные проверки import/export используют подставленные пути.
- Developer ID identities: 0. Есть только ad-hoc подпись. Нотаризация и проверка
  скачанного из интернета/quarantined артефакта Gatekeeper не выполнены.
- Windows/Linux проходят прежний набор в CI; локальный Mac не заменяет их native
  приёмку. macOS CI использует отдельный runner arm64; результат CI см. в PR.
